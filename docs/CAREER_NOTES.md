# Interview and résumé notes

Confirm individual contributions to group work before claiming personal ownership.

## Suggested project entry

**Riverfire Ops — ICT Project Management Portfolio Case Study**

- Developed an academic hybrid delivery case study combining Microsoft Project planning with a Taiga backlog containing 4 epics, 7 stories, 20 tasks and 8 recorded issues.
- Extended the case study with an browser prototype demonstrating synthetic crowd scenarios, stale-data handling and incident acknowledgement.
- Documented requirement-to-feature traceability, proposed RAID controls and release gates, and added automated tests for core simulation logic.

Do not describe this as paid work, an operational event platform, a $4.799M project you delivered or a measured safety improvement. Replace the first bullet with confirmed responsibilities if you contributed to only part of the group coursework.

## Five-minute walkthrough

Explain the event ICT problem and hybrid planning decision. Show a source acceptance criterion in the delivery board. Switch to a surge, inspect the zone, log an incident and acknowledge it. Show the sensor outage and explain why unknown readings must remain visible. Finish with traceability gaps and the release evidence needed for production.

## Questions to practise

- Why separate infrastructure dependencies from Agile dashboard delivery?
- How do you reconcile sprint review claims with an open board snapshot?
- Why does the total exclude stale feeds?
- How does recording an announcement differ from delivering one?
- How would you estimate and govern the delivery-receipt change?
- What would you validate before real use?
- Which parts came from coursework, and which were added for the portfolio?
